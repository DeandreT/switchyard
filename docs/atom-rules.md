# Atom Rule Administration

The opt-in HTTPS administration listener provides a closed create/get/list/delete rule profile under existing ordinary subscriptions. It shares mandatory TLS, the fixed audience and HTTPS SAS Manage policy with [subscription administration](atom-subscriptions.md). It does not add credentials, listener options or a domain/store format. The correlation projection declares Chrono 0.4.45 and pinned ICU4X case-map/data providers 2.2.0 and 1.3.2; existing lockfile package versions are retained.

## Requests

| Operation | Request | Response |
| --- | --- | --- |
| Create | PUT /{topic}/Subscriptions/{subscription}/Rules/{rule}, no If-Match | 201 with the prepared static description |
| Get | GET /{topic}/Subscriptions/{subscription}/Rules/{rule} | 200 with a static description, or 404 |
| List | GET /{topic}/Subscriptions/{subscription}/Rules | 200 with an Atom feed |
| Delete | DELETE /{topic}/Subscriptions/{subscription}/Rules/{rule}, empty body | Empty 200 after the original deletion commits |

All requests require `api-version=2024-05` or `2021-05`. Get/List accept absent `enrich` or `enrich=False` only. List accepts decimal `$skip` in 0..1000 and `$top` in 1..100, defaulting to 0/100. Every If-Match condition, including `*`, is refused; rule update is not implemented. Read/delete/list bodies must be empty.

## Closed Definition

Create accepts Atom entry/content containing a Service Bus `RuleDescription` with explicit Name and Filter. Name must exactly match the decoded route leaf. Filters are `xsi:type="TrueFilter"` with exact SqlExpression `1=1`, `FalseFilter` with `1=0`, `SqlFilter` with an exact bounded native SQL source, or `CorrelationFilter` with the typed subset below. Each accepted bare type must resolve to the Service Bus namespace at that element. SQL/Boolean Parameters may be absent or empty; correlation uses its own system fields and Properties instead. Optional Action uses the bounded native semantic-v2 profile below. Nonempty parameters, empty/unknown action shapes, CreatedAt and unknown properties are refused rather than approximated. Missing names/filters are never defaulted.

Names preserve case, surrounding spaces, Unicode and literal percent. They must be nonblank, XML-legal, at most 50 UTF-16 units, and contain no controls or `/`, `\`, `@`, `?`, `#`, `*`; dot/dotdot leaves are refused. The subscription must meet the existing ordinary Atom scalar profile, including `requires_session=false` and the hidden 262,144-byte per-copy message limit. Parent topic settings remain native, not a fabricated Azure topic quota profile.

Responses include matching leaf title, explicit Name/typed Filter and an optional accepted SqlRuleAction, with no creation date or runtime counts. SQL remains a concrete `SqlFilter` even when its source is `1=1` or `1=0`; it is not relabeled as a Boolean filter. Get projects only the selected compatible rule after complete stored-set health checks. List first validates the complete set's representability, then selects a page: an unsupported rule outside the requested page still refuses the whole list. Healthy native rules with unsupported correlation values/key collisions, legacy-v1 actions or XML-illegal action sources can coexist with compatible single-rule Get and ordinary Create/Delete, but are not silently stripped or hidden by List. Projectable correlation and semantic-v2 action rules are included normally.

The native maximum is 32 rules per subscription (including $Default), 64 KiB per stored rule and 256 KiB per complete set. Small raw HTTP pages are supported; normal pinned SDK top=100 requests fit one page. Empty feeds use paired start/end tags, not a self-closing element. No SDK multipage or rule-date claim follows.

## Bounded SQL Profile

SQL uses the existing native semantic version 1 and compiler, described in [SQL Rules](sql-rules.md); no new parser implementation, durable format or serialized executable plan is added. The exact once-decoded source is retained without trimming, case folding, rewriting or constant aliasing. It must be XML-legal and compile within the existing native grammar: at most 1,024 UTF-16 units and 4,096 UTF-8 bytes, 128 physical tokens/nodes, depth 32 and 32 IN items. Native complete-set compilation and evaluation budgets remain unchanged; these are bounded logical work limits, not a universal CPU/RSS guarantee. No predicate parameters or additional predicate grammar are enabled. Optional actions use the separate bounded profile below.

XML 1.0 input normalizes raw CR/CRLF once to LF; an explicit numeric `&#13;` remains CR in the decoded source. Responses escape retained CR as a numeric reference and emit the exact source with empty Parameters. This is codec/raw HTTP fidelity, not a promise that an SDK constructor's original literal CR survives its own XElement/XmlWriter request path. No expected-source normalization substitutes for that unproved SDK boundary.

The shared response preflight counts both Name occurrences and predicate/correlation text plus any action-source bytes before the existing sixfold XML-escape reservation. Present Action markup adds 256 separate checked bytes; property markup and the checked reply sink/full-feed preflight remain bounded and return no partial successful feed. All current stored rules are decoded and natively compiled before selected lookup or whole-set projection. Healthy action-bearing rules project only when their semantic-v2 source meets the bounded action profile; otherwise compatible filter types do not make an unsupported action representable.

## Bounded Correlation Profile

A bare Service Bus `CorrelationFilter` carries optional CorrelationId, MessageId, To, ReplyTo, Label (native subject), SessionId, ReplyToSessionId and ContentType. Strings are retained ordinally, including an explicit empty field as Some-empty; absent stays absent. An empty filter remains typed Correlation, not a Boolean alias. Optional Properties contains Service Bus KeyValueOfstringanyType entries with one Key and one typed Value. Value `xsi:type` QNames must resolve to `http://www.w3.org/2001/XMLSchema`; prefixes are not hardcoded. Duplicate fields, keys or entries and unknown nodes/types are refused.

| XSD Value Type | Native Value |
| --- | --- |
| string | Exact XML-legal String |
| int | Signed Int32, without widening |
| long | Signed Int64 |
| boolean | Boolean; true/false or 1/0 input |
| double | IEEE-754 Double, including negative zero and INF/-INF; every NaN payload refused |
| dateTime | Timestamp with exact whole-millisecond absolute value |

DateTime requires a valid lexical year 1..9999, calendar and explicit Z or +/-hh:mm zone at most +/-14:00; normalized UTC must also remain in years 1..9999. Missing zones, leap seconds, nonzero sub-millisecond digits and range crossings are refused. Replies use UTC with three fractional digits. The server preserves the resulting timestamp, not original zone spelling or CLR DateTime Kind. Null, unsigned/smaller integer widths, Float, decimal, Char, Uuid, Binary, Symbol and compound values are not coerced or stringified; duration/TimeSpan has no native scalar projection.

At most 32 combined present system fields and application properties are admitted. Key spelling is never normalized or merged. Distinct native keys that collide under the declared equality-only .NET 8.0.31 Linux ICU 78.3 profile are refused: Unicode 17 BMP with the CLR fixed page/Latin1 exceptions, and Unicode 15 supplementary casing. This matches the pinned SDK property dictionary boundary for that model, not every .NET/NLS/invariant/ICU environment. Non-colliding Unicode, empty and whitespace keys remain exact. Strings/keys must be XML-legal. Numeric character-reference CR is retained; raw XML CR/CRLF normalizes once. SDK writers may omit empty/whitespace system strings or transform constructor values before HTTP; codec/raw HTTPS fidelity does not establish that constructor boundary.

Checked response preflight counts all system/property text and scalar bounds in the existing sixfold escape reservation, then adds 256 checked markup bytes per property. Full-set projection still precedes pagination, and the 1 MiB sink returns no partial successful feed. Projection validation does not precheck native encoded size: a legal oversized direct DTO retains original after-stamp 503, and duplicate creation retains its original earlier stamped priority. Healthy unsupported native correlation, legacy-v1 action or XML-illegal action siblings are preserved, while selected unsupported Get or complete List refuses; native corruption is checked before selection/page.

## Bounded SQL Action Profile

An optional Action must be a bare Service Bus xsi:type="SqlRuleAction" with one explicit SqlExpression. Its own Parameters may be absent or empty; filter and action expressions/parameters are separate fields. Missing action type/expression, duplicate action/expression/parameter nodes, unknown types/nodes, nonempty parameters, empty action shapes and supplied semantic-version fields are refused. Absent Action stays None. Responses retain an accepted action rather than dropping it.

The projection reuses the complete existing native semantic-v2 compiler described in [SQL Actions](sql-actions.md), not a new action parser or evaluator. Sources support unqualified or user-qualified REMOVE and SET to exact String, Boolean or signed Int64 literals, including checked extremes and unary signs. Quoted target spelling is retained. System mutations, parameters, null/floating/computed values, property expressions and additional Azure/CLR grammar are not enabled. Existing limits remain 4,096 UTF-8 bytes, 1,024 UTF-16 units, 128 physical tokens and 32 statements, with the native parser-depth and complete-set compilation/evaluation budgets unchanged.

Exact once-decoded source is retained without trimming, rewriting or case folding. XML legality and bounded native compilation are checked before desired child/profile admission and stamping. Raw XML CR/CRLF normalizes once; numeric CR survives and replies escape it as a character reference. This is codec/raw HTTPS source fidelity, not proof that an SDK constructor retains an original literal CR. Checked response preflight includes action-source text in the existing sixfold escape reservation, then adds a separate 256 checked markup bytes for each present Action. Correlation property markup remains separately reserved; the existing 1 MiB sink returns no partial successful feed.

Native stored health is checked before selected Get or whole-set projection. Healthy stored semantic-v1 REMOVE remains unprojectable because the wire shape cannot preserve its semantic version; it is not silently relabeled v2 or stripped. Healthy XML-illegal native action source likewise remains unsupported. Compatible selected Get and absent lookup can coexist with those healthy siblings, but selected unsupported Get and complete List refuse, including off-page rows. Corrupt action grammar or version retains the native health error before selection/page, not a profile refusal. Delete keeps the original planner and can remove a healthy v1 row without requiring its projection.

Create with an action uses the original CreateRuleWithAction planner and still returns the prepared DTO without a postcommit read. Only the targeted Rule and Clock records change; existing messages and other rows are untouched and no delivery wakeup is published. Valid duplicate, native encoded-size and stored mutation errors retain their original after-stamp priority. No native-size precheck, action-free retry, new message evaluator, domain/store format, dependency, route or rule-update behavior is introduced. The dedicated fixed-source [SQL-action SDK CRUD lifecycle](#sql-action-sdk-lifecycle-verification) passed both pins, backends and constructors as administration evidence. The separate fixed [HTTPS-to-AMQP rule bridge](#https-rule-message-bridge-verification) passed both pins/backends with both administration constructors and named-key AMQP, checking transformed and untouched copies with independent settlement; no general action/conversion claim follows.

## Authorization

Only structural `Subscriptions`/`subscriptions` and `Rules`/`rules` markers are canonicalized to lowercase, before BOTH literal ResourceScope creation and owner selection. Topic, subscription and rule spelling remains unchanged. Thus `/Orders/Subscriptions/Worker/Rules/Keep` selects `Orders/subscriptions/Worker/rules/Keep`; alias-only scoped SAS credentials do not gain canonical access. URI path and audience segments decode once, with token form encoding as a separate layer.

A subscription literally named Rules remains a subscription member; terminal primary `topic/Subscriptions` paths retain ordinary queue behavior. Authority comes from the configured host/namespace, never Host, forwarding headers, socket port, SNI or XML. Manage precedes operation/XML/body polling and owner work. The original grant is rechecked immediately before STARTING the asynchronous owner operation, not at eventual enqueue/execution; timeout or cancellation does not revoke already-admitted work.

## Owner Effects

Each operation runs in one serialized owner turn. Create validates the desired name/filter/action, including SQL predicate source/version/XML legality and bounded compilation, correlation type/count/XML legality/key-collision checks and optional semantic-v2 action source/XML legality/bounded compilation, inside that owner turn BEFORE child/profile admission and command stamping. An invalid direct DTO therefore performs no stamp/apply; HTTP XML/definition failures occur earlier, before calling BrokerHandle. Current-child admission proves complete metadata/capacity exclusions and live child identity, then minimal live parent Topic identity and the closed subscription profile. Get/List use the complete bounded fenced rule getter before selection, validating every stored rule's key/name/topology/size and native SQL/action semantics. They stamp no command, apply no batch and retain stored timestamps/bytes.

Create/Delete use the original child-fenced planners. Success stamps once and atomically writes only the targeted rule Put/Delete plus Clock. No configuration, message, deadline, DLQ, identity, counter or other rule row is rewritten; no deliverability wakeup is published. Create returns its checked prepared definition without a postcommit read. Duplicate creation remains an error, not overwrite/no-op. Deleting `$Default` when it is the only rule leaves a genuinely empty set; nothing recreates it automatically. An empty set or sole False rule routes no subscription copy, while explicit True recreation restores matching delivery. Already retained copies stay untouched. Explicit recreation stores the new command's domain timestamp, which is not projected onto the wire.

Missing-child admission is bind-first, pre-stamp 404; it is NOT an orphan-rule/whole-ledger health proof or repair. On a live child, duplicate Create and missing-rule Delete stamp once, apply nothing and do not advance durable Clock. Stored admission/profile corruption and pure-read failures are pre-stamp. Malformed stored RULE values in mutations retain original AFTER-stamp planner priority, not a new pre-read shortcut. Stale child fences after delete/recreate fail before stamping; identity fencing is not a configuration compare-and-swap.
